# mbp-os — piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un'immagine bootc `ghcr.io/drdamnation/mbp-os:stable` installata in automatico sul MacBook Pro 2012 con schermo rotto. L'interruttore `ujust modo pc|server` sceglie tra PC su HDMI e serverino, e SSH con chiave funziona sempre.

**Architecture:** È una copia ridotta di air-os (`C:\Users\danie\projects\air-os`): base `ghcr.io/ublue-os/base-main:44` + `kmod-wl` precompilato, `build_files/steps/NN-*.sh` (uno per area) e `system_files/` copiati su `/`. Il modo lo decide un **generatore systemd** che legge `/etc/mbp-os/mbp.conf` a ogni avvio:
- in modo `pc` fa puntare `default.target` a `graphical.target`;
- in modo `server` lo fa puntare a `multi-user.target` e maschera Docker.

Gli stack si avviano con `avvia-stack`, derivato da nas-os. La ISO è quella di bootc-image-builder con un kickstart automatico, costruita in CI. In locale le si aggiungono il profilo Wi-Fi e le chiavi extra con `mkksiso`, e il `%post` li copia nel sistema installato.

**Tech Stack:** bootc/Fedora 44, dnf5, GitHub Actions, cosign, bootc-image-builder (anaconda-iso), lorax `mkksiso`, QEMU+OVMF (prova in CI con KVM), bash, systemd generator, Docker CE/moby + compose, Tailscale, niri + DMS + greetd.

**Spec:** `docs/superpowers/specs/2026-11-03-mbp-os-design.md`

## Review Focus

1. `mbp.conf` mancante, vuoto, con CRLF, con spazi o con un valore sbagliato (`MODO=Server`, `MODO=pc # nota`). Atteso: modo `server` con un avviso nel journal, mai un avvio senza SSH. Test in Task 3.
2. Modo `pc` con container `restart: always` già creati: Docker non deve farli ripartire. Atteso: `docker.service` e `docker.socket` mascherati a runtime. Test in Task 3 e in VM (Task 9).
3. Un avvio fallito o un'interruzione di corrente non devono lasciare il menu di avvio in attesa di un tasto. Atteso: il menu riparte da solo. Test in VM (Task 9).
4. La chiavetta USB può risultare `sda` e il disco interno `sdb`. Atteso: il `%pre` sceglie il disco per modello; se trova 0 dischi o più di 1, l'installazione si ferma senza toccare nulla. Test statico in Task 7 e in VM in Task 9.
5. Il profilo Wi-Fi viene copiato con permessi diversi da `600 root:root`, e NetworkManager lo ignorerebbe senza dirlo. Atteso: `600 root:root`. Test in VM (Task 9).
